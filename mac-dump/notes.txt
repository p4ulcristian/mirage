## CRITICAL FIX FOR VIO

The VIO config in `viture_vio.cpp` has the WRONG camera model:
- Current: `camera_model: pinhole` ❌
- Correct: `camera_model: equidistant` ✓ (fisheye camera)

The Beast uses a fisheye world-facing camera. The Carina VIO engine
has these camera models (from strings in libcarina_vio.dylib):
- `pinhole` - standard rectilinear projection
- `equidistant` - Kannala-Brandt fisheye (r = f*theta)

SpaceWalker's strings confirm fisheye usage:
- `fisheye_cam0`, `cam_use_fisheye`, `init_equidistant_with_fisheye_stereo_rectify`

## Key Findings

### 1. VIO Config Schema (from libcarina_vio.dylib strings)
The engine expects this YAML format:
```yaml
cam0:
  camera_model: <pinhole|fisheye>
  distortion_model: <radtan|equidistant>
  intrinsics: [fx, fy, cx, cy]
  distortion_coeffs: [k1, k2, k3, k4]
  resolution: [width, height]
  T_cam_imu: [4x4 matrix]
  timeshift_cam_imu: <float>
```

### 2. Camera Model Types Found
- pinhole
- fisheye (with equidistant distortion)
- "fisheye" flag: cam_use_fisheye

### 3. What's MISSING (not in resource files)
- Beast/R6 specific camera intrinsics (not in any yaml)
- T_cam_imu extrinsics for Beast camera
- Camera resolution for VIO (separate from display)

### 4. Where Camera Calibration Likely Lives
Options:
a) Hardcoded per-model in libcarina_vio.dylib
b) Pulled from device firmware at runtime via HID
c) Embedded in the SDK for each device generation

### 5. ORB Database Path

Database is 44MB - this is the loop-closure vocabulary that prevents long-term drift.
